# Chapter 08 — ledger

| Folk claim (named retelling) | Record (document, page/section) | Verdict |
|---|---|---|
| Wired calls Maersk's mutually synchronising domain controllers a “decentralized backup strategy.” | Gavin Ashton, “Maersk, me & NotPetya,” “Finding our feet”: Maersk's disaster-recovery processes covered loss of a site or datacentre, but not loss of every controller at once. Microsoft, “Determine how to recover the forest,” says forest recovery restores a controller from an available, trusted backup and warns that dangerous data can replicate back into the recovered forest. Live replicas were useful for availability, but shared the destructive state and failure boundary. | OVERSTATED |
| Wired says one controller survived in Ghana because a blackout had taken it offline. | Ashton, “Finding our feet,” confirms that Active Directory had to be restored and that the first restored controller ran on a Surface Pro 4. The fetched Maersk reports do not identify Ghana or a blackout. No fetched company document settles those details. | OPEN |
| BleepingComputer says the M.E.Doc update servers were responsible for the initial NotPetya infections. | Cisco Talos, “The MeDoc Connection,” Summary and backdoor analysis: its incident responders concluded that all installations came through the M.E.Doc update system and tied the observed execution to modified update code. Microsoft, “Delivery and installation,” separately reports telemetry showing the legitimate updater process executing the malicious command. | HOLDS |
| The update-server shorthand implies that one poisoned download on 27 June was the whole delivery mechanism. | DOJ indictment ¶¶34, 37–38 (allegations): three update files were allegedly modified before 27 June; the June file installed command capability; traffic was then temporarily rerouted to deliver NotPetya. Cisco, “Details” and backdoor analysis, reports stolen administrator credentials, a reconfigured proxy and code modified on multiple occasions. | MISSING |
| BleepingComputer says the M.E.Doc update mechanism did not use HTTPS or cryptographically signed binaries. | No fetched primary M.E.Doc specification, binary or forensic report establishes the signing state. Cisco documents stolen credentials, server configuration changes and modified code, but does not say whether update binaries were signed. | OPEN |
| BBC calls the event the “NotPetya ransomware attack.” | DOJ indictment ¶33 alleges the ransomware purpose was a ruse and that the accused could not decrypt victims' files after payment. ESET, “Diskcoder.C outbreak,” independently explains why its modified disk code made recovery impossible. The label describes the disguise, not the malware's function. | WRONG |
| Darknet Diaries says that after about nine days Maersk had a functioning network again. | Maersk, “What we learned from the NotPetya Virus cyber-attack,” says it rebuilt its network in ten days while cargo kept moving. “Functioning” and “rebuilt” are different thresholds, so the retelling turns an approximate milestone into a single recovery finish line. | OVERSTATED |
| Darknet Diaries says NotPetya ultimately cost Maersk USD 350 million. | A.P. Moller–Maersk, *Annual Report 2017*, printed pp.29 and 54, reports approximately USD 250–300 million, including lost revenue, restoration and extraordinary operating costs. | WRONG |
