# Chapter 02 — pitches (standard mode: user picks; nothing drafted yet)

Sources for every number below are in `resources/sources/02/SOURCES.md`. No pitch is marked chosen.

## A. Three defaults, not one
Anchor: JIRA SERVER-4216 (Debian package "listens on all interfaces by default", filed 2011-11-04,
closed 2014-04-08 with 2.6.0-rc0), the 3.6 release-notes sentence "From MongoDB versions 2.6 to 3.4,
only the binaries from the official MongoDB RPM … and DEB … packages would bind to localhost by
default", and JIRA SERVER-28229 with commit 60636b4 (2017-04-25/28, fix version 3.5.7) — read
against Matherly's July 2015 finding that the default "took a bit more than 2 years to change" and
his December 2015 finding that people running new versions were "changing the default configuration
… to something less secure". Folk claim tested: "MongoDB shipped insecure by default until the
ransom wave forced a fix" (Register 9 Jan 2017: "up until recently, the software's default
configuration is insecure"; TNW Nov 2017: "will no longer come with an unsafe configuration out of
the box"; Wikipedia § Security). Defense: the change from a *package* default to a *binary* default,
plus the startup warning "** ATTENTION: The server is bound to localhost" — with the record that the
packaged default had existed for three years and did not reach the cloud images and old versions the
wave actually hit (Gevers: "about 78% of all these hosts were running known vulnerable versions").
Takeaway: a default that lives in a distribution's config file is not a default of the product, and
a default only protects the installs that take it.

## B. What the count counted
Anchor: the Gevers/Merrigan tracking sheet (first tab exported) read against the day-by-day press
sequence built from it — "just over 1,800" (Matherly, 4 Jan), 10,500 "about 25% of all MongoDB
databases accessible via the Internet" (Bleeping, 7 Jan), "12,000 … to 27,633, over the course of
about 12 hours" (Register, 9 Jan), "at least 29,000 … erased" (Krebs, 10 Jan), 26,000 more in
September. Folk claim tested: "27,000 databases wiped in a weekend" — the number is real, but it is
a count of ransom-note database *names* seen through Shodan while "attackers are deleting each
others' ransoms as quick as they pop up" (Merrigan), against three different denominators (99,000
per Gevers; ">52,000" per Shodan on 10 Jan; ~42,000 implied by Bleeping's 25%), and Gevers found
in 84 cases no "trace of data exfiltration", so "held for ransom" mostly meant "deleted". Defense:
the instrument itself — the same Shodan query that found victims is the query a defender runs
first, and MongoDB's own January post points at a Cloud Manager alert for "if a host is exposed to
the public internet". Takeaway: before you repeat a breach number, ask what was counted and by whom.

## C. Did the exposed count fall?
Anchor: the exposed-host series as the record actually gives it — Shodan ~30,000 (Jul 2015),
35,000 (Dec 2015), ">52,000" (Krebs quoting Shodan, Jan 2017), "99,000" (Gevers via the
Register); then, after 3.6 GA (8 Nov 2017), Shodan's May 2020 post (exposed MongoDB *data* "from
24 TB to 12.5 TB … drastically decreased") against ZDNet's July 2020 host figure ("From the 60,000
… in early 2017, the needle has barely moved to 48,000", with 22,900 of them ransomed again in one
2020 campaign). Folk claim tested: "the default changed to localhost and the exposed count fell" —
which is also the line in CONTEXT §3, so this pitch tests the book's own premise. Defense: the 3.6
default, honestly measured — it removed the failure mode for fresh installs (Horowitz: "that entire
method of doing ransomware goes away") and demonstrably did not reach the installed base, cloud
images, or admins who set `bindIp: 0.0.0.0` from a tutorial. Takeaway: a changed default is a
slow-release defense; you have to measure what it reached, and the honest verdict is data-volume
fell, host-count is OPEN.

## D. "You need to use these features correctly"
Anchor: the vendor's three statements in sequence — Nilsson, 6 Jan 2017 ("These attacks are
preventable … You need to use these features correctly"; "The most popular installer for MongoDB
(RPM) limits network access to localhost by default"), the SERVER-28229 spec seven weeks later, and
the 8 Nov 2017 press release ("this default behavior is implemented directly in the server itself").
Folk claim tested: "MongoDB blamed its users" (ZDNet 2020 on Ottenheimer, "blamed the attacks — and
rightfully so — on database owners"). Defense: the vendor's own change as the record of what the
vendor thought the fix was, set against what it said in January. Takeaway: read a vendor's statement
during an incident next to the change it ships afterward; the gap between them is the real
post-mortem.

## Recommendation
Pick **A**, with B's day-by-day counts as the spine of the break section and C's after-series as the
defense section. A is the only pitch whose anchor is the vendor's own record (two tickets, a commit,
the release-notes sentence) rather than press, so the ledger's strongest rows — the packaged default
existed from 2.6.0 in April 2014 (WRONG for "until the wave forced a fix"); the binary default was
spec'd in March 2017 and merged in April, seven months before 3.6 GA (MISSING); Matherly's 2015
warning that new versions were being reconfigured insecurely (MISSING) — are argued from documents
the reader can open. It also meets CONTEXT §6 ("a default, not a bug … the default-bind change; the
exposed count afterward") once B and C are folded in; on its own it would not. One thing to settle
before drafting: the record does not support "the exposed count fell" as CONTEXT §3 states it — data
volume fell (Shodan), host count barely moved (ZDNet, unsourced) — so §3/§6 need an §8 amendment to
"exposed data fell; the host count is contested" or the chapter must say so in the defense section.

Cost of the others: **B** alone makes a chapter about counting rather than configuration and leaves
the defense at "run the scanner yourself", which is thin against §6. **C** alone puts the
weakest-documented figure in the corpus (ZDNet's 60,000→48,000, no stated source) at the centre and
would need Shadowserver's feed, which was not obtained. **D** alone hands the chapter to the vendor's
rhetoric, needs the unfetched Ottenheimer post to be fair, and gives the reader no mechanism to draw
on a whiteboard.
