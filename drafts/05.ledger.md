| 2 | "Although Progress was quick to respond and released a patch the same day, MoveIt instances were already under attack" (TechTarget); "An advanced and persistent threat actor used a sophisticated, multi-stage attack to exploit this zero-day vulnerability" (Progress spokesperson, quoted by TechTarget). | 3 | "An attacker could submit a crafted payload to a MOVEit Transfer application endpoint" (Progress KB, 9 and 15 June; the same sentence is the CVE description) — the picture every reader forms is a form field with a quote mark in it. | Rapid7 analysis: "naive injection attempts fail - in every case the application correctly escapes the arguments. The actual issues wound up being quite a bit more complex!" The first patch deleted `SetAllSessionVarsFromHeaders()`, which "reads key: value pairs from the X-siLock-SessVar header" and is "only called from machine2.aspx in the session_setvars transaction"; that page "is actually fetched by localhost (::1)" after a call to the ISAPI DLL. Huntress: "moveitisapi.dll is used to perform SQL injection when requested with specific headers, and guestaccess.aspx is used to prepare a session". Rapid7's traced path runs from session state (`this.m_pkginfo.LoadFromSession()` in guestaccess.aspx) through four calls to `UserGetUsersWithEmailAddress()`. The form inputs were escaped; the value came in by a door the escaping never saw. | MISSING |
| 4 | "SQL injections succeed because software developers fail to treat user-supplied content as potentially malicious" (CISA/FBI Secure by Design alert, March 2024, written about this campaign); plaintiffs: SQLi is "low-hanging fruit" (Bellwether Complaint as recited in MDL Order 22). | Rapid7's published diff of the pre-patch `UserGetUsersWithEmailAddress()`: the format-string argument array is `InstID` at {0}, `this.siGlobs.objUtility.EscapeLikeForSQL(EmailAddress)` at {1}, and `EmailAddress` raw at {2}; the statement uses `Email='{2}'` for the equality clause and {1} inside the `BuildLikeForSQL` clauses. The developers did treat the input as hostile — for the LIKE clauses — and passed the same value unescaped into the equality clause of the same statement. The patched version binds all four values with `where.WithParameter(...)` and calls `DoReadQuery(where.GetQuery(), where.Parameters, ...)`. Escaping is a per-use promise; one unescaped use of an already-escaped value is the whole bug. | MISSING |

| 6 | "the number of impacted individuals also surpassed the 60 million mark" (TechCrunch, 25 Aug 2023); "approximately 93.3 million individuals" (Wikipedia lede); "62,054,613 individuals" (TechTarget). | Emsisoft, the source of all three: "there will be some overlap in terms of individuals impacted ... we have no way to account for this"; 2,773 organisations / 95,788,491 as of June 2024. | 7 | Progress "deployed a patch on May 31 that fixed the issue" (spokesperson, quoted by TechTarget). | Rapid7 analysis: on 9 June Progress "released a second patch to address several parts of an exploit chain that were not fully mitigated by the first patch"; `moveitisapi.dll` "wasn't meaningfully changed in the first patch (it would later be patched in the second patch)".
